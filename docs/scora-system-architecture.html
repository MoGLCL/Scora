01

نظرة عامة على المنتج وأطراف المنصة (Product Context)

سياق العمل

منصة سكورا (Scora) هي منظومة عمل عربية موجهة لسوق العمل التقني في مصر والشرق الأوسط، تهدف إلى حل مشكلة التوظيف التقليدي المبني على السير الذاتية وحفظ الأسئلة النظرية، من خلال قياس الفهم العملي الفعلي للكود، وكشف الاعتمادية المفرطة على الذكاء الاصطناعي، وتوليد درجة ثقة (Trust Score) مبنية على أدلة سلوكية صلبة أثناء البرمجة.

👨‍💻 المطور (Developer)

يبني بروفايل موثق، يخوض تقييمات تفاعلية في محرر Monaco، يكتسب نقاط مهارة (SP)، يعرض مشاريعه بالـ Markdown، ويتلقى عروض التوظيف المباشرة.

💼 العميل (Client)

ينشر مشاريعه باقتراح الميزانيات الذكية، يراجع عروض المطورين مع التحقق من درجات الثقة وفهم الكود، ويوظف المطور المناسب عبر محادثات فورية.

🛡️ مدير النظام (Admin)

يدير المنصة عبر لوحة تحكم متكاملة تشمل مراجعة قبول المطورين، إدارة النزاعات، ضبط نماذج الـ AI وكوبونات الاشتراك، ومراقبة سجلات التدقيق.

طبقات التطبيق الداخلية وهيكل الكود (Internal Layers)

Clean Architecture
مخطط B — طبقات هيكل المشروع والمسؤوليات البرمجية

⚡ Server Components (RSC)

تُنفذ مباشرة على السيرفر لقراءة البيانات من الـ DAL وعرض الـ HTML جاهزاً دون تحميل العميل مكتبات جافاسكريبت زائدة، مما يمنح أداءً وتجاوباً فائق السرعة.

🔒 Data Access Layer (DAL)

مركزية التحقق من الجلسات والصلاحيات؛ تستخدم دالة verifySession() مع ميزة cache() من React لمنع تكرار استعلامات التحقق أثناء دورة التصيير الواحدة.

05

مسار الطلب ودورة حياة الصفحة (Request Lifecycle)

Flow Sequence
1. وصول الطلب إلى الحافة (Edge): يستقبل ملف proxy.ts الطلب ويتحقق بشكل متفائل وسريع من توقيع JWT عبر jose دون لمس قاعدة البيانات.
2. معالجة الـ Root Layout: يتم قراءة الجلسة الكاملة عبر verifySession() والتحقق من حالة المستخدم (نشط / محظور) وجلب تفاصيل الدور.
3. حقن الـ Providers: يقوم ProfileProvider بحقن بيانات المستخدم في شجرة الـ Client Components دون الحاجة لطلب API إضافي.
4. تنفيذ الـ Server Actions: عند قيام المستخدم بإرسال نموذج، يتم استدعاء Action مباشر مشفر يتم فيه التحقق بواسطة Zod وتنفيذ الاستعلام بقاعدة البيانات.

07

محرك الثقة وخوارزميات التقييم (Trust Engine Deep Dive)

Core Innovation

يمثل محرك الثقة قلب سكورا التقني؛ وهو نظام متعدد الطبقات يلتقط الأدلة أثناء خوض المطور لتقييمات برمجية حية، ويحولها لمؤشرات رقمية دون إصدار أحكام عشوائية، مع مراعاة فلسفة واضحة:

📐 مبادئ المحرك الفلسفية

  • القياس وليس الحكم: طبقة الخصائص تجمع حقائق رقمية فقط.
  • التأكيد المزدوج: لا يتم رفع نسبة المخاطرة إلا بتطابق طبقتين مستقلتين.
  • غياب الدليل ليس دليلاً على الإدانة: القيم الفارغة لا تعتبر صفراً.
  • المراجعة البشرية الحتمية: القرارات المصيرية ترفع للمراجعين في الطبقة العاشرة.

🎯 مخرجات التقييم الثلاثية

1. درجة الثقة (Trust 0–100): مدى دعم الأدلة لملكية وفهم الكود.

2. درجة المخاطرة (Risk 0–100): قلق مؤكد عبر أكثر من طبقة سلوكية.

3. درجة الثقة بالأدلة (Confidence 0–100): جودة واكتمال البيانات المقاسة.

سجل القرارات المعمارية (Architectural Decision Records)

10 ADRs
ADR-001: اعتماد Next.js App Router و Server Components
مقبول ومطبق (Accepted)
السياق: الحاجة لبناء صفحات عربية سريعة جداً تدعم الـ SEO بأقل حجم جافاسكريبت للعميل.
القرار: استخدام RSC كأساس لجميع الصفحات وحصر Client Components في عناصر التفاعل فقط.
ADR-002: استخدام Raw SQL مع mysql2 Pool بدلاً من ORM
مقبول ومطبق (Accepted)
السياق: الحاجة للتحكم الكامل في الأداء ومنع استهلاك الذاكرة الزائد في بيئات التشغيل الخفيفة.
القرار: استعلامات SQL نقية ومؤمنة بـ Parameterized queries عبر lib/db.ts.
ADR-003: عزل محرك الثقة في حزم مستقلة (Monorepo Packages)
مقبول ومطبق (Accepted)
السياق: منطق التقييم وحساب الثقة يجب أن يكون قابلاً للاختبار المستقل وإعادة الاستخدام.
القرار: تقسيم المحرك إلى 10 حزم نقية داخل مجلد packages/ مع أكثر من 100 اختبار وحدوي.
ADR-004: تكامل الذكاء الاصطناعي عبر OpenRouter
مقبول ومطبق (Accepted)
السياق: إمكانية تبديل نماذج الـ AI وضبط الحصص دون الحاجة لتغيير كود التطبيق.
القرار: بوابة موحدة للذكاء الاصطناعي تدعم التبديل المباشر من لوحة الإدارة.
